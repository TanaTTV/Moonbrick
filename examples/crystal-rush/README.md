# Crystal Rush integration example

`python scripts/create-example.py <new-folder>` creates a full Rojo project, bundled kit/specs, a deterministic map, server round/cooldown/economy rules, saved coins, touch/gamepad-friendly ProximityPrompt pickups, server-fed HUD and Studio DebugHooks. No tool install, asset upload or Studio changes occur.

Run `bash tools/check.sh`, then `rojo build default.project.json -o crystal-rush.rbxlx`. Open **this new local place**, connect the project's Rojo server, and start a playtest. Minimum one player; multiplayer shares one server round. Collect crystals within 45 seconds; coins persist in published games and reset in Studio by default. This example is not intended for production publishing without the V1 acceptance gates.

Art direction: Moonstone Garden palette, matte slate map, saturated amethyst Glass shards with restrained purple lights. Each crystal is **3 instances: 1 anchored WedgePart + 1 ProximityPrompt + 1 PointLight**. Nine crystals total **9 lights** (Brightness 0.35, Range 7, no light shadows), 9 collectible parts, 27 collectible instances; the entire generated arena has 15 BaseParts. No idle particles, extra cores, or Neon surfaces. Collected crystals switch their lights off; the next round restores their original transparency (0.08) and lights. The generated place has one BloomEffect (Intensity 0.08, Size 12, Threshold 1.5) to limit hue washout. Rendered hue/contrast and mobile performance still require review. The primitives make installation self-contained; replace them with approved Blender exports after import and screenshot review. `assets/art.json` is the shared art contract. Blender source can be generated with `assets/blender/example_scene.py` and exported with `scripts/assets.py`.

Workspace streaming is enabled in the generated `default.project.json`: minimum radius **64 studs**, target **128 studs**, appropriate for the **80 × 80 stud** arena. The server owns the complete crystal registry, prompt triggers, distance/movement checks, claims, rewards and round reset. The HUD only uses replicated Kit/Shared modules and server snapshots; dependency waits have 10-second timeouts and it never waits for, enumerates, or counts Workspace crystals. Native prompts become available as their parts stream in, including late arrivals, without client crystal bindings to rebuild. Streaming a crystal out cannot reset its server claim or award coins. The streaming radii are not scriptable, so they come from the built place (`rojo build`); in a place you only live-sync with Rojo, set `StreamingEnabled` and the radii once in Studio's Workspace properties.

## Device support

Designed for touch, keyboard/mouse and gamepad. The informational HUD has no buttons or selectable controls; it cannot capture movement input. A UIScale driven by the device-safe frame size keeps it in the upper centre below `GuiService:GetGuiInset()`, with 12px margins and a 120px (short landscape) / 160px lower control reserve. `ScreenInsets = DeviceSafeInsets` clips to device safe areas; viewport, safe-origin and top-bar changes recompute layout. Refusal notices share the same panel instead of a separate top-bar toast. Standard native prompts provide the interactive touch target (verify at least 44px in emulator), explicit **E / gamepad X**, short **Collect / Amethyst** text, one visible prompt globally, and line-of-sight checking. No custom prompt scaling or HUD selection navigation is needed.

Orchestrator Device Emulator checks, in a **new disposable local place built from this project**, memory stores only:

1. **Phone 320 × 568 portrait**, touch emulation: spawn, walk with the thumbstick, jump, approach a crystal and tap **Collect**. Title, state/timer and Crystals/Coins must remain readable, inside safe bounds, below the top bar and clear of both bottom control zones. Prompt text must fit and its tap target measure at least 44px; one successful tap increments both counters by exactly one. Show a refusal notice and verify it fits too.
2. **Phone 568 × 320 landscape**, then rotate while playing and while a notice is visible. Repeat movement/jump/collection. Panel must resize without clipping, stale positioning, overlapping controls or capturing touch input. Repeat on a notched phone preset in both orientations; no text may enter a notch/home-indicator area.
3. **Tablet 768 × 1024 portrait / 1024 × 768 landscape**, touch emulation: repeat the same checks. HUD should remain centred and modest in size (scale capped at 1.25), with one readable prompt and unobstructed controls.
4. **Console 1920 × 1080**, Controller Emulator or physical gamepad: move/jump with the controller and collect using **X**. HUD must remain inside the device-safe area and display the same authoritative result; no mouse or GUI selection should be necessary. Also verify PC **E** and window resizing.
5. **All presets, graphics quality low and high**: capture before pickup, after pickup and next round. Shards should stay recognisably purple rather than white; collected shard/light/prompt disappear, and transparency/light/prompt restore on the next Playing round. Check only `CrystalBloom` exists in the fresh built place, record FPS/frame time and instance/light counts; emulator screenshots do not establish real-device performance.
6. **Streaming and authority, Local Server + 2 Players**: verify Workspace streaming/radii in Edit before play, shared countdown and separate scores, then walk normally around the map and respawn. For actual stream-out/in, add a disposable walkable extension and walk well beyond the target radius and back (no teleport bypass); confirm streamed descendants leave/reappear using streaming diagnostics. If retention prevents stream-out, record that gate as unverified. HUD must continue through absent/late crystal instances; a crystal claimed by the other player must stay hidden/disabled on arrival. Duplicate/distant requests and teleport/speed-hack pickups must award nothing; teleport attempts must still be pulled back by `Rules.plausibleMove`.

These are pending rendered/input checks, not results established by headless validation. The pure layout suite can run separately without Roblox: `python examples/crystal-rush/tests/run-layout.py --luau .artifacts/tools/luau/luau.exe` from the repository root. In a generated project, use `python tests/run-layout.py --luau <path-to-luau>`; `K.test()` also discovers `HUDLayout.spec` in Studio. The repository's existing `scripts/test-luau.py` remains unchanged and runs the shared persistence/gameplay/Rules suites.

Acceptance in a dedicated place:

1. `K.test()` passes; round moves Waiting → Intermission → Playing → Results.
2. `K.hook("CrystalRush", "state")` reports the actual server state; `skip` advances the deadline.
3. Real ProximityPrompt input awards exactly one coin, hides one crystal and updates HUD; duplicate and distant `CrystalCollect` requests award nothing. Teleporting the character next to a crystal is pulled back by the server movement check and awards nothing.
4. Two players see the same countdown; each sees their own score/coins. Leave/respawn works without stale UI or data access.
5. Touch and gamepad can collect and read the HUD; screenshot-review lighting, contrast and small-screen layout.
6. A separate test experience validates real save/load and shutdown; use no production player keys.

Local type checking/building and pure rules can be tested without Studio. These do not prove the six acceptance steps above.
