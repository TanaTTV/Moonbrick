# Import an existing game

The plugin root is two folders above this skill's base directory (`<base>/../..`); call it `KIT`. Uses pinned Rojo 7.7.1 `syncback` to read a saved `.rbxl` or `.rbxlx`; fidelity has specific limits below.

1. **Get a place file.** Ask the user to save their game from Studio: File → **Save to File As…** → `.rbxl`. (Publishing alone isn't enough; syncback reads a local file.) Get the path.
2. **Project folder + name** (default `~/RobloxProjects/<game-name>`), then create it like `/moonbrick:new`: `bash "KIT/scripts/new-project.sh" "<dir>" "<name>"` (tell the user what gets installed first if Rokit is missing).
3. **Import:** `bash "KIT/scripts/import-place.sh" "<dir>" "<path/to/place.rbxl>"`. Requires a fresh scaffold. Stages native syncback, validates, then promotes a service-mirroring layout for ServerScriptService/ReplicatedStorage/ReplicatedFirst/ServerStorage/StarterGui/StarterPlayer scripts. Workspace (including its scripts), terrain and lighting stay in the original place. Existing game code and reserved Kit/Tests/MCPKit collisions are refused; rename in a copy or plan custom mappings. No automatic git staging or commit.
4. **Review before running anything:** inspect `git -C "<dir>" diff --stat`, untracked imported files, and `.moonbrick/import-report.json`. Read every imported script/model; the advisory scan is not a security certificate and can flag comments or miss obfuscated code. Do not playtest untrusted scripts until reviewed. Run `bash "<dir>/tools/check.sh"`; summarize imported diagnostics by kind. Preserve strict kit libraries; relax legacy game code only with an explicit compatibility decision. Previous mappings are in `.moonbrick/backups/`.
5. **Connect safely:** the user opens the **same** place in Studio, then Rojo → Connect. Rojo shows a diff; it should be empty or tiny (kit files added). If it wants to delete or change many things, stop and investigate before accepting.
6. Commit only the reviewed import files, then `/moonbrick:review` and a design doc if needed. Never delete the original saved place.

## Fidelity limits

`python scripts/test-import-fidelity.py` generates its own large/UI/rig/world fixtures, builds both input formats with real Rojo, runs both shell entry points, then rebuilds XML and compares imported services. It compares every property present in either XML tree, checks sibling name/class order for every parent, and prints the top per-class/per-property measured-default exemptions. It checks duplicate siblings by original ordinal and reports ambiguous identity rather than guessing a match. Binary input uses the XML build of the same source project as its baseline, not a second syncback. Use `--keep <empty-dir>` to inspect the generated places and imports.

- **World ownership:** Workspace, its scripts/terrain, Lighting and Atmosphere are deliberately absent from the imported mapping (`scripts/project.py:import_config`). Their values are not exported into `src` or supplied by the code-only rebuild. Keep the original place open when connecting; the rebuilt file is not a replacement for the complete game. Root `$ignoreUnknownInstances` preserves omitted services in the mapping. This offline test verifies that boundary and byte-identical saved input, not a Studio connection diff or terrain voxel/rendering fidelity.
- **StarterPlayer settings:** `ENTRIES` imports only `StarterPlayerScripts` and `StarterCharacterScripts`. Service properties such as `CharacterWalkSpeed` and `CameraMaxZoomDistance`, plus children outside those containers, stay owned by the original place. For a standalone rebuilt place, add reviewed custom mappings/properties explicitly. The test exempts only its two omitted service settings, never changes to their values.
- **Script line endings:** syncback keeps the script file bytes, but `.lua`/`.luau` reads in [Rojo 7.7.1's Lua middleware](https://github.com/rojo-rbx/rojo/blob/v7.7.1/src/snapshot_middleware/lua.rs#L66) normalize CRLF to LF during rebuild. The test reports only that exact conversion as expected; every other Source change fails. Prefer LF before migration in a copy; retain the original if byte-identical CRLF Source is required. This does not authorize rewriting the user's saved input.
- **Reference attributes:** [Rojo's reference linker](https://github.com/rojo-rbx/rojo/blob/v7.7.1/src/syncback/ref_properties.rs#L100) adds `Rojo_Id` and `Rojo_Target_<property>` attributes to preserve links. The test accepts only new attributes tied to actual original targets and verifies rebuilt Model.PrimaryPart/Motor6D.Part0/Part1 paths. Existing user attributes remain compared. Avoid using these Rojo-reserved names for game data; review their additions in the connection diff rather than stripping them.
- **Default serialization:** model blobs may materialize omitted engine defaults; syncback [filters defaults from metadata](https://github.com/rojo-rbx/rojo/blob/v7.7.1/src/syncback/property_filter.rs). The test measures exact defaults with a generated binary-model probe using the same pinned Rojo. Only omission/materialization of that measured value is expected; changed non-default values fail.
- **Sibling order:** directory-backed imports rebuild in filesystem enumeration order ([directory middleware](https://github.com/rojo-rbx/rojo/blob/v7.7.1/src/snapshot_middleware/dir.rs#L47)); explicit project children use a sorted [BTreeMap](https://github.com/rojo-rbx/rojo/blob/v7.7.1/src/project.rs#L352), [iterated during rebuild](https://github.com/rojo-rbx/rojo/blob/v7.7.1/src/snapshot_middleware/project.rs#L201). Original sibling order is not stored by those mappings. The test reports `order_filesystem` only for an exact name sort at a parent proven to have a directory in actual syncback output, with unique names and the same name/class sequence after sorting. Other permutations, order changes inside model blobs, and duplicate-name ambiguity fail. This limit includes the two explicitly mapped StarterPlayer script containers. Keep model blobs or add reviewed explicit UI ordering such as LayoutOrder when original order matters.

The synthetic acceptance exercises UDim2/Color3/sequences/Font/enums, rich text/unicode, attributes/tags, duplicate names, deep nesting, and a generated Motor6D/Bone/Attachment/KeyframeSequence hierarchy. It does not prove arbitrary place fidelity, uploaded mesh/animation dependencies, terrain voxels, rig playback, rendered UI, or live connection behavior. Those remain separate Studio acceptance gates. No assets are downloaded and no imported scripts are executed by this test.
