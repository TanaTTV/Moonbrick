# Changelog

## 1.1.0-beta.1 (unreleased)
Beta of the creative engine and design workflow (branch `v1.1/creative-engine`), plugin version 1.1.0-beta.1. **The nine 1.0 waivers are still open and move to 1.2** (touch, gamepad, phones, 2-player streaming, live DataStore scenarios); nothing here verifies them. Evidence and gaps: [docs/v1.1/LEDGER.md](docs/v1.1/LEDGER.md).
- **Creative Kit:** `Fx` (layered effects on a shared `Scheduler`, pooling, Low/Medium/High quality, markers, hitstop, time scale; `Fx.emit` adapts RoClicks' MIT Emit convention), `Motion`, `Pose` (R15/R6, rig-checked clips with markers), `Audio`, `Tex`, `Geo` (procedural meshes dressed on clients). The V1 `VFX` and `UI` APIs are unchanged.
- **UI shape language:** `UI.useTheme` with `buttonFill`, `displayFont`, `panelStroke`, `panelTransparency`, `labelStroke`; defaults reproduce 1.0. `VFX.Style.titleFont`.
- **Creative brief:** the game-design skill asks at most 3 questions or offers 3 directions, handles hybrid genres and reference images, and runs a top-3 screenshot loop. `assets/art.json` records the direction; `assets.py theme` generates `ArtStyle.luau`. Guide: [docs/DESIGNING.md](docs/DESIGNING.md).
- **Removed the demo games** (Crystal Rush, Element Brawl and the three V1.1 showcases), `create-example.py` and their CI builds to keep the plugin lean.
- **Tools:** `scripts/fxtex.py` (effect textures) and `scripts/sfx.py` (placeholder sounds), stdlib only, with upload-free Studio previews on your own PC.
- **Cards:** creative APIs live in `tools/KIT_CREATIVE.md` (22 KB, read only for visual work); the core card grew by 0.3 KB.
- **Fixes:** generated mesh faces were inside-out; clients' 8-mesh EditableMesh limit is handled by baking fixed-size copies.
- **Fx/Geo review fixes:** torus/shard layers fall back to ring/wedge parts when meshes can't be made (published games without "Allow Mesh & Image APIs"), and a layer that fails to build no longer leaks the effect; `Geo.cached` builds each key once even for concurrent first callers, and `Fx.preload()` warms Fx's mesh shapes at startup; overlapping `freeze` calls no longer freeze forever, and a 60 s real-time watchdog ends any effect; `Fx.play` runs its first step on the next frame, so `:on()` listeners see events at t = 0. Headless tests cover each.

## 1.0.0 (2026-10-19)
First stable release. 4 of 13 stable gates passed in Studio; the other 9 were waived by the owner and deferred to v1.1 ([details](acceptance/v1-stable/WAIVERS.md)). **Known limitations, not yet verified:** Device Emulator touch layouts, a real gamepad, real-phone performance, 2-player streaming, live DataStore engine restart, natural 10-minute lock expiry, two independent live servers, real provider outages, and an interactive `/reload-plugins` session.
- **Element Brawl showcase** (`python scripts/create-example.py <dir> --example element-brawl`): a Smash-style platform fighter with damage-percent knockback, blast zones, stocks, four element specials (Flame Dash, Frost Lance, Thunder Blink, Gale Burst), double/recovery jumps, a side-on framing camera, bots, a damage HUD and saved Wins/KOs, built on Net, Cooldown, Round, PlayerData, VFX and UI. Its rules run in the headless Luau suite and the generated project is type-checked and built in CI. Playtested in Studio 0.743: every special and the strike apply their exact damage, launches reach player and bot, KOs, eliminations and results work.
- **Faster, cheaper sessions:** every project ships `tools/KIT_API.md` (a generated ~15 KB signature card) and checked `tools/recipes/` (data, pickups, ability, shop); the skills point there instead of the Kit source. Same-batch benchmark: median cost equal to plain Claude Code ($0.217 vs $0.220), about 23% faster, with session-locked saves in 3/3 runs.
- `tools/check.sh` keeps diagnostics in order and caps output at 40 lines.
- Blender → Studio: the assets skill now requires Animation Editor *Rest Pose Source = Imported Rig* (the default lays rigs flat) and matching Scale Unit; static/PBR, rig/animation and terrain import passed in Studio.
- Player disconnects and server shutdowns during loads and saves (with injected provider faults) verified in Studio; reusable fault harness under `acceptance/v1-stable/lifecycle/`.
- New banner rendered from a scripted Blender scene (`.github/assets/blender/hero.py`) and a rewritten README.

## 1.0.0-beta.1 (2026-10-15, beta)
Beta, not a stable 1.0. Evidence per requirement, including what was **not** tested, is in [docs/V1-BETA-LEDGER.md](docs/V1-BETA-LEDGER.md).
- Live DataStore acceptance passed on a disposable private experience (7/7: round-trip, session-lock contention, stale-lock takeover, shutdown flush, invalid-data refusal + recovery, retry/backoff; no leftovers, 51/60 requests). Not yet run live: real engine shutdown/restart, natural 600 s lock expiry, two-server contention, real provider throttling.
- Measured Claude Code benchmark ([docs/BENCHMARK.md](docs/BENCHMARK.md), n=3 per condition): with the plugin merely installed the skills were not invoked on a terse prompt; when told to use Moonbrick they were, with session-locked saves in 3/3 runs (vs naive DataStore in 6/6 baseline runs) at about 1.9x median cost. No token saving is claimed. Start with `/moonbrick:new`.
- Remote GitHub marketplace install verified; bench harness path handling fixed for Windows 8.3 and macOS `/private/var` temp directories; benchmark tests run in CI.
- Rojo startup ownership on Windows walks a native process snapshot instead of PowerShell/WMI (which took up to 20 s, the whole SessionStart budget); the install test stops a Rojo orphaned by a hook timeout on its own port only.
- Add a confined, artifact-first Claude Code coin-pickup benchmark harness with exact reported accounting and independent headless/static scoring; measured results are in docs/BENCHMARK.md.
- Harden disposable DataStore acceptance with a bounded universe listing gate, run-authored writes and cleanup, cooldown-tolerant headless Main coverage and strict CI checks; ignore departed Net callers before rate limiting and strip Unicode controls from rejection reasons.
- Require listener ownership before install-runner cleanup, allowlist child environments and fingerprint real settings; compare all import properties/sibling order with visible default exemptions and an original-place notice; retain non-PBR texture sizes and report missing Blender action slots clearly.
- Plugin version 1.0.0-beta.1 so `claude plugin update` refreshes installed 0.1.0 copies (verified by the isolated install test).
- Harden Net rejection reasons, warning summaries and departed-player tracking; isolate install-runner credentials/tools/config snapshots and validate cleanup PIDs. Clarify example-only Workspace/Lighting configuration.
- Add real Rojo 7.7.1 synthetic XML/binary import fidelity acceptance for large hierarchies, UI and rigs, with measured timings/file counts, strict loss detection, validated reference/default exceptions, byte-identical input/script/managed files and intact Kit. Document CRLF rebuild normalization, StarterPlayer settings and world ownership; Studio connection/terrain/rendering acceptance remains open.
- Use automatic Blender material node trees on 5+ without accessing the deprecated `use_nodes` toggle; preserve legacy behavior before 5.0.
- Format the headless harness and PlayerData with the template StyLua rules; check shipped Luau, the harness and examples in CI.
- Add bounded Net rejection counters with isolated snapshots, active-player cleanup and per-remote summaries limited to once per minute.
- Add isolated Claude Code fresh-install/0.1.0 plugin-upgrade acceptance, exact cached component hashes, empty-cache tool bootstrap, installed-copy scaffold/check/build and SessionStart checks. Document reinstall for same-version local marketplace upgrades; support a fast `--skip-tools` mode.
- Add a self-contained, default-refusing DataStore acceptance project with place/universe gates, synthetic keys, bounded requests/cleanup, memory-only headless validation, and owner runbooks for two-server contention, timed expiry and shutdown/restart. The base suite has since passed live (see above).
- Fix false-success checking, failed/stale sourcemaps, partial type downloads and formatter failure handling; include dynamic MCPKit in checking/linting.
- Replace destructive import with staged validation/promotion, backups, reserved-name refusal, advisory script scan and no automatic git staging. Preserve non-imported world content and explicit project settings.
- Add transactional/idempotent managed updates with backups, missing service-preservation settings and safe ignore migration. Project scripts require Python 3.10+.
- Fence PlayerData with per-session tokens, serialized snapshot writes and DataStore metadata preservation. Retain failed leave saves for shutdown/retry; reject corrupt/unserializable data; cancel failed/yielding update callbacks. Lost sessions reject access and kick by default.
- Studio defaults to memory even with API access. Explicit `studioStore = "live"` is for a separate test experience; no provider-error memory fallback. Deprecated lock bypass is ignored.
- Harden Net validators, remote class/name checks, duplicate registrations, finite rate limits, client timeouts and yielding request concurrency.
- Fix Rojo MessagePack identity handling, loopback-only startup and foreign-listener preservation. Pin/checksum Rokit and Luau bootstraps.
- Bound/cancel MCPKit recordings, fix typed Rojo attributes, reject empty all-replace edits and complex lossy exports. Fix stale UI visibility tweens and idle camera-shake callbacks.
- Add optional native Blender FBX workflow, shared art manifests, four-map SurfaceAppearance PNG emission, rig/skin/active-action metadata and native static/PBR/rig/animation round-trip tests. Enforce texture, bone and four-influence budgets with source preservation and new-output-only promotion; Studio import/rendering remains a manual acceptance gate.
- Add server Cooldown/Round/Economy libraries and a complete buildable Crystal Rush example with server-fed HUD, shared rounds and validated pickups.
- Crystal Rush: enable Workspace streaming (64/128 stud minimum/target radii), bounded client dependency waits and a HUD independent of streamed crystals; replace full Neon collectibles with saturated amethyst Glass shards, nine modest shadowless lights and restrained Bloom. Add a device-safe responsive HUD with in-panel notices, explicit E/gamepad X native prompts, pure layout specs and an exact Device Emulator/streaming checklist. Preserve server pickup authority and movement validation; rendered/device/performance acceptance remains pending.
- Add cross-platform CI, host/headless/isolated Studio regressions, actual 0.1 upgrade checks, real Rojo integration and measured output benchmark.
- QA fixes: `PlayerData.set`/`increment` reject non-finite/unserializable values; a final save with invalid data still releases the lock (keeping the last good save) instead of locking the player out for 10 minutes; failed manual saves warn. `K.logs()` no longer misses warnings raised in the same call. `K.audit()` reports its true total and refuses to run in playtests (engine scripts produced hundreds of false positives). Crystal Rush HUD label reads "Crystals".
- Stability follow-ups: saved data that fails validation is refused once (no retry storm), never overwritten, and can be recovered with the opt-in `onInvalidData` callback (`PlayerData.sanitize` provided); the original is kept in a bounded `backups` list and recovery refuses rather than discarding a backup. Crystal Rush checks movement against a server-trusted position, pulling back teleports/speed hacks before the pickup distance check. Project sync/import only rejects links in the paths it manages (`src`, `tools`, `tests`, `.moonbrick`, project files), so `node_modules` links no longer block upgrades. A `serve.lock` left by a killed launch is reclaimed after 60 s; a live one reports "startup in progress" instead of "File exists". CI authenticates Rokit to avoid GitHub API rate-limit failures. The Windows listener-ownership check allows for slow WMI startup (3 s → 20 s timeout).
- Known gaps in this beta: real-device touch/gamepad and Device Emulator checks, Blender FBX import/rendering in Roblox, terrain import, and the extra DataStore scenarios listed above.
